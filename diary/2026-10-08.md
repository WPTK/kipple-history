# 2026-10-08 (Thursday): toolchain pin, parser bounds, one redirect rule

Four merges, all late in the evening, all aimed at input Kipple does not control. Nothing was tagged. The hardening pass that
these belong to is written up in [2026-10-09.md](2026-10-09.md); this entry records what landed on the 8th.

## What changed (all merged to main, unreleased)

- **Toolchain (#322, 22:20).** The Go toolchain is pinned to a patch release (1.27.2) with `golang.org/x/net` v0.60.0, and the
  image build now refuses a Go release other than the one `go.mod` names, so the binary and the checks read one toolchain.
- **Feed documents (#323, 22:57).** Nesting depth and the number of entries one fetch keeps are bounded. A document nested more
  than 512 elements deep is refused as not a feed; one fetch keeps at most the newest 2,000 entries, and the feed's Fetch log
  says when entries were left out.
- **Housekeeping (#328, 23:31).** Deploy rollback wording, the Dependabot configuration and the `tools` module's `x/net`.
- **One redirect rule (#330, 23:59).** Every outbound client (feeds, adding a feed, full-text pages, icons, proxied images)
  follows the same redirect policy: web addresses only, no step from https down to http, no Referer or embedded credentials
  carried along.

## What it taught

- The redirect rule was the fourth place a request policy had been written by hand. Centralising it was cheaper than the
  review rounds the copies would have needed, and it is the reason the next day's follow-ups (#337, #339) were small.
- A pinned toolchain is only a control if the build fails when the pin drifts. The image check is the part that matters.

## Open
