## CI skips heavy jobs for prose-only pull requests (Kipple PR #278, squash `a5ca37f`)

Root cause of the cost: every pull request ran the full Go, web, security and image jobs, including ones that only edit docs.
The Go job alone takes 11 to 17 minutes.

Design as merged: a `changes` job classifies the diff using the base commit's copy of the classifier script and the allowlist
`scripts/ci-prose.txt`. It fails closed: any failure or doubt means everything runs. The four required checks (go, web,
security, docker) still report, because a skipped job satisfies a required check; the dependent jobs use
`!cancelled() && needs.changes.outputs.code != 'false'`. When the diff contains code, CI first deletes the listed prose files
before the go, web and docker jobs, so any test that quietly reads one of those files fails on its own.

It took four review rounds and three designs:

1. A denylist of the docs that tests read. Review found it fail-open and incomplete.
2. An allowlist plus a scanner that looked for file names in test sources. Review found false positives and no way to make it
   complete.
3. Delete the prose files and run the tests (the one that merged), recommended by the Opus reviewer. A reader that exists
   cannot be missed, because it fails.

Live proof on a throwaway draft pull request: the whole main CI run took about 22 seconds. Two required checks passed and two
were skipped, and the pull request showed CLEAN and MERGEABLE.

## Review process findings

Every pull request in this stretch got an Opus review at high effort, and every finding was fixed. Reviewers now hand back at
most 15 lines. An earlier whole-diff review handed back incomplete, which led to the same diff being reviewed twice at Opus
prices; the fix is the rule that a reviewer works alone and finishes before anything else is started on that diff.

## Working economy decisions (owner, 2026-10-06)

- Batch related small pull requests into one.
- Cheap checks first, expensive gates once, on the commit being tagged.
- The auto-fix monitor is only for pull requests that touch code, workflows or dependencies.
- One task or one release per session.
- The global instructions file was trimmed; server-specific detail moved to a file that loads only in sessions started on
  the Kipple server.
- Unused connectors (Docs, Drive, the visualiser) are off by default.
- Models: Opus for review, root-causing and design; Sonnet for everything else; never Haiku.

The savings are estimates, not measurements. The largest are expected to be fresh sessions per task, reviewers that work
alone, and running the expensive gates once. CI minutes on prose-only pull requests should drop by about 99 percent. These
need measuring over the next few sessions.
