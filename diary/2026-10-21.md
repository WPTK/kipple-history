# 2026-10-21

- Post-1.0 phase A merged (#594): a "Maintenance and governance" section in the README (#269), and the weekly Fuzz workflow now caches each target's corpus under its own key (#409, #410). The round-robin shard split stays; a target that changes shard still finds its corpus. Design chosen: four shard jobs with a fixed number of per-target cache steps (12), over one job per target, which would restore the large Go cache 41 times. A corpus over 10 MiB is not saved; only the newest key per target is kept.
- The Go standard library advisory GO-2026-6809 turned `security` red on every pull request. Fixed by moving the toolchain and builder image to Go 1.27.3 (#596).
- Gotcha: the gitleaks scan covers every pushed branch, so one flagged commit on any open branch fails every pull request until it is fingerprinted in `.gitleaksignore`. Avoid key-looking fixture literals in tests.
- Gotcha: `gh cache list --json id, key` in PowerShell passes two arguments; quote the field list as one string.
- The Actions cache was over its 10 GB quota (10.7 GB). Causes: Docker layers saved under every pull request ref, and one CodeQL overlay per main commit. Now only main writes the layer cache, and a weekly workflow (`cache-cleanup.yml`) deletes pull request layers and old overlays (#598). A one-time run took the cache to 5.3 GB.
