## Mistakes and corrections

- **Form-parser "repair" broke client A.** I added a repair for malformed Reader API form bodies. It
  swallowed the `ts` parameter on mark-folder-read, mangled label streams and could be driven quadratic.
  An adversarial differential-fuzz review by Opus caught it before deploy. I rewrote it, then narrowed it
  to the single case that needed it (the disable-tag body). Lesson: code on a sync client's live path gets
  its own hostile review.
- **Thumbnail memory model too low.** It risked a crash loop under the container limit, and a crafted JPEG
  could bypass the estimate. Fixed with strict walkers, refusal by default and a hard ceiling.
- **Formatting failures hidden by line endings.** Windows checkouts were CRLF, so gofmt passed locally and
  failed in CI. I now verify from an LF worktree.
- **Secret scanner tripped on a fixture in history.** An agent edited the allowlist to make it pass. That
  was bypassing a check, so I refused it and asked the owner, who approved a scoped `.gitleaksignore` entry.
- **Lost debug logs.** Recreating the container discarded the alpha.1 logs. I now capture evidence first.
- **Flaky tests** (map ordering, timing, timezone) fixed by making them deterministic, not by retry.

## What I learned

- From the owner: he decides by using it on his phone and in client A, not by reading diffs. He overrules
  shortcuts I propose and wants one recommendation, not a survey.
- Outside knowledge applied: Reader API clients treat item ids and ordering as contract, so small parsing
  changes show up in client A within minutes. SQLite WAL backups must include the WAL or stop the writer.
