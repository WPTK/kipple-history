# 2026-10-07 (Wednesday): the Gazette, stats, the restore fix and 0.8.0-beta.5

One long multi-agent day that ended in a release. The owner said "tag, release and deploy" in chat in the evening.

## What shipped in 0.8.0-beta.5

- **Security fix, restore-upload binding (#302, #305).** In the setup wizard, an attacker who could reach the instance during
  a restore could confirm the owner's upload. The upload is now bound to the browser that made it: the page holds an owner key
  and sends it only as a request header. Four or more review rounds. Beta.4 had the hole; beta.5 could not ship without the fix.
- **Schema 17 and 18, `feed_daily_new` (#287, #312).** Exact per-feed daily arrivals, stored as runs of counted item ids. Schema
  16 to 18 in one start took 0.14 s in the rehearsal on a copy of the live snapshot.
- **Stats (#37).** Previous-period comparison and a Months range (#301) that compares only complete days and marks a coverage
  gap (#306); a drill-down sheet per feed (#309); a per-feed read rate (#312).
- **Fetch spreading (#310, #289).** Each feed gets its own slot in the interval, with a per-install salt, and an RSS `ttl`
  fix. No more bunching after a long downtime.
- **Gazette layout (#39).** Planner (#299), renderer (#308), wiring (#313): newest first always, a paper name setting, and
  mark-as-read while scrolling.
- **Offline (#253).** Badges move at once in a session (#297) and survive a relaunch (#311); #253 is closed.
- **Smaller:** reset notice (#300), generic wording for reader apps and servers (#298), Vitest worker cap (#303).

## What went wrong, and what it taught

- **Scroll and marking code needs many review rounds.** #313 took six, and each found a real bug. jsdom stubs fire
  observers synchronously, which hid the real frame ordering. Tests for this code need to model the order, not just the result.
- **A docs caveat meant the behaviour was wrong.** The per-feed read rate first shipped as a capped approximation with a docs
  note. Review pushed on the caveat, and the rate became exact counting (CHALLENGES 74).
- **Measure a subagent's "flake" claim.** `TestASlowUploadIsStopped` was reported as flaky; it was a real race, fixed in #305.
- **The deploy helper cannot find the pre-migration snapshot.** The app writes it without logging its name. Follow-up.
- A GitHub outage in mid-afternoon delayed pushes; work stayed committed locally and went up afterwards.

## After the tag

- **Pre-migration snapshot name (#318).** The deploy helper refused to run because the app never logged the snapshot's file
  name. For this deploy the snapshot was copied off the server by hand (read-only copy, checksum verified). The app now logs
  the file name (base name only), and the rollback docs say where to find it.
- **README screenshots (#319) and the website (website PR #13).** Both show the beta.5 build.
- **Mute similar (#320, merged for the next release).** The owner opened "New filter" through "Mute similar..." on a phone and
  the suggestion chips were greyed out; they had never added those words. Cause: the editor pre-filled the first three title
  words. The owner ruled the pre-fill out ("that behavior sucks") and asked that very common words never be offered. Result:
  the rule starts empty, chips toggle with a check mark, about 550 English function and filler words are skipped, and the
  server's text normaliser now treats typographic apostrophes as plain ones (the first, page-only fix had made a chip whose
  rule matched nothing; CHALLENGES 79). Three review rounds, every finding fixed.
- **Follow-ups opened.** #314 (Gazette swipe and row menu), #315 (article previous and next follow the page's reading order),
  #316 (trim notice and read rate disagree about a large commit's earlier chunks).
