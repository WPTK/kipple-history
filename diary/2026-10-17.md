# 2026-10-17 (Saturday): the 1.0.0-rc.1 candidate and the phone shakedown

The overnight run reached a release candidate on `main`, and by mid-morning it was tagged, published and deployed. This entry is written from the
public record only: merged pull requests and issues of the Kipple repository, and its changelog. Times are US Eastern (UTC-4).

## The candidate

- #414 to #417 (open at the end of 2026-10-16) were reviewed and merged through an integration branch, so one merge landed the
  candidate: #418, the `1.0.0-rc.1` release commit (04:10). It supersedes #413. `0.9.0-beta.2` was dropped and folded into rc.1;

## The phone-size shakedown

- Method: the app driven in a WebKit browser with iOS user agent and touch, emulating iPhone 17, iPhone 17 Pro and iPhone 17 Pro
  Max sizes (portrait, and one landscape size), on a seeded instance. Screenshots were reviewed by eye for clipped text, menu
  placement and dead ends, not just checked by script.
- #426 (06:47), phone shell fixes. Stats scrolled the whole document because the scroller had no positioning and its hidden
  tables were placed against the page. The Feeds title was squeezed to an ellipsis by text labels that appeared from 400 px wide.
  The list header jumped in height because its title row wrapped. The tab bar lit Unread for every list path, because a nav link
  only marks its own route. The reader's title and body had different widths because the measure was in `ch`, which resolves
  against each element's own font size; it is in `rem` now.
- #427 (07:01), menus and copy. The layout menu used a fixed 8 px collision padding, blind to the bottom tab bar and the
  home-indicator area; it now measures the bar when it opens. "Email - Compact" became "Headlines". The Saved searches help text
  stopped being keyboard-only wording, the Muted empty state stopped repeating its header, the Devices list puts this device first
  with an icon from the user agent, and the native number spinner is hidden in the stepper field.
- #428 (07:15), the changelog fold of the eleven fragments from #426 and #427 into the rc.1 section, plus a fix to the chrome UAT
  flow's picture check so it counts only pictures that have finished loading and only wrapper boxes.
- Lesson: several early failures were harness bugs that looked like app bugs. WebKit does not load off-screen lazy pictures, and
  two layouts put the aspect class on the `img` itself, so the picture check reported empty boxes that were not there. A probe
  that reported a clipped title (S8) was correct once the real cause was found: the title link was inline inside a truncating
  heading, so its rectangle was the unclipped text. The app was fixed, the probe was left alone.

## Tag, release and deploy

- 10:26 tag `v1.0.0-rc.1` on `main` at `11cb2402` (the head after #430). The release workflow ran green (12 minutes). 10:39 the
  GitHub pre-release was published with the container image by digest, a keyless signature checked against the tag's workflow
  identity, and a signed SPDX software bill of materials. The release notes carry a "Known issues in this release candidate"
  section: the landscape row menu (#431), the What's new dialog on a fresh install (#435) and the phone polish list (#432).
  The first two were fixed on `main` within the hour.
- The release was deployed to the Kipple server by image digest, not by tag.
- Merged just before the tag: #429 (the UAT and release docs, 09:31) and #430 (UAT flow fixes, 10:12). #429 wrote the day's
  process lessons into `docs/maintainers`: a Suite 6 phone-size shakedown, a "Harness pitfalls" list (lazy images in WebKit,
  the aspect class on the `img`, external navigation stranding a phone run, waiting for the library to load, heavy browser runs
  alone on the machine) and "Running suites in parallel" (docs, site, history, restore drill, Suite 2 and static gates may run
  at once on separate instances; the tag, release workflow, deploy and Suite 5 run strictly in that order).

## After the tag

Eight pull requests merged on `main` after the tag, one at a time. They are in no tagged build; they wait for the next
candidate.

- #433 (11:09), fixes #431: the row More menu fits a landscape phone and scrolls.
- #434 (11:23), documentation defects found by UAT Suite 5, the fresh-machine Docker walkthrough.
- #436 (11:36), fixes #435: the What's new dialog no longer appears on a brand-new install. Cause: the web app used "no feeds
  yet" as its first-run signal, and the setup wizard adds feeds before the app first mounts, so a new install always looked
  like an upgrade. The server now records the running version as seen when it creates the account, and the web heuristic is
  gone (see [CHALLENGES.md](CHALLENGES.md) item 93).
- #437 (11:39), the agent rows of the 1.0 release checklist filled in against rc.1, with evidence. Owner rows were left

  clearer settings hints, third-party app names removed from comments.
- #438 (12:19), documentation fixes from a cold read: README release candidate wording, a Quick start at the top of the deploy
  guide, a "Running Kipple safely" section in SECURITY.md, third-party reader app names removed from the design doc.
- #440 (12:32), the `kipple restore` command now runs the same backup schema check as the web restore. The two had separate
  checks and the command's had fallen behind; both now share one.
- #441 (12:46), accessibility fixes from the rc.1 review: every screen sets a document title, the What's new dialog returns

- Dependency update pull requests #442 to #445 (Go, tools, npm, actions) were opened and are still open.

## Process lessons (public docs)

- Run independent work in parallel on separate instances, and keep the ordered release steps serial. Both rules are written
  into `docs/maintainers/uat-plan.md` and `release-checklist.md` (#429).
- Check the harness before the app. The list of pitfalls above came from this day's false alarms (item 92).
- The post-tag merges went in one at a time, 7 to 22 minutes apart, so each pull request met the `main` the previous one left.
