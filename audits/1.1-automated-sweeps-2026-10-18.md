## Mistakes made on the way (tooling, not product)

- A fuzz function cannot call `f.Helper` or `f.Fatal`; a harness shared across iterations has to point at the iteration's own `*testing.T`.
- Go's default minimization (60 s per interesting input) stalls heavy stateful targets: pass `-fuzzminimizetime`.
- The first crash test grew a database to 1.8 GB (unpaced writer), checked a growing list, and counted a dead writer as a kill.
  Fixed: paced writer, an early exit is a failure, zero committed batches is a failure, a pass removes its temp directory.
  Process ids are reused on Windows, so names built from them collided; a per-run value fixed it.
- PowerShell cannot pipe binary output (use the tool's own output flag), skips the proxy for loopback addresses, and drops a
  list passed through `-File` after its first element.
- gremlins v0.6.0 panics with `--output` or three workers on this machine; it needs a large `--timeout-coefficient`.
- A request body checked by a handler (`read` is required for mark-read) made a load script report 100% failure.

## How to repeat

Fuzz lanes: `.hunt/lane.ps1`; crash test: `go run ./scripts/crashtest`; live instance: copy a scale library, run the
released binary with `KIPPLE_DATA` and `KIPPLE_ADDR` on loopback; benchmarks twice, then compare the two runs with
benchstat before comparing with the baseline.
