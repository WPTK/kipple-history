# 2026-10-09 (Thursday): hardening pass after 0.8.0-beta.5

A planned pass over how Kipple treats input it does not control: feeds, pages, images, backups and requests. Nothing was
deployed or tagged. The next beta waits for the owner's word.

## What changed (all merged to main, unreleased)

- **Feed documents.** Nesting depth and the number of items one fetch keeps are bounded, with tests built from hostile documents.
- **Toolchain.** The Go toolchain is pinned to a patch release and checked against the image build; a dependency was updated.
  The Go linters moved to their own module so they read the same toolchain as the build.
- **One redirect rule** for every outbound request, plus request deadlines, a shared rule for the private-network exception and
  checks on stored cache validators.
- **Full-text pages, discovery, icons and feeds** refuse a body in a compression nobody asked for.
- **Cloudflare Access key fetch** uses the guarded transport.
- **Server.** Explicit request header size, a cap on open event streams (503 with Retry-After), `private, no-store` as the
  default for responses that set no cache policy, and image addresses that cannot be signed are dropped.
- **Stored text.** Item titles are plain text. Stored article HTML is cleaned again after a restore or a policy change.
- **Fuzz seeds** from the hostile documents were added for the feed parser and the OPML importer.

## What it taught

- A tool that "passes" can pass vacuously: the linters could not read the new toolchain's export data, so moving them into
  the repo's own tool module mattered more than any single fix.
- A pre-scan in front of a parser must read exactly the bytes the parser reads (control bytes, declared charset), or the check
  is bypassable by the thing it guards.
- Review of the combined diff found real gaps the per-PR reviews missed (restore stubs not cleaned, a writer held too long,
  a title parser eating text); close-out review of the whole range is worth its cost.
