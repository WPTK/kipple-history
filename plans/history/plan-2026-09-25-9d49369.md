# Kipple — master plan (2026-09-24)

## Context

The owner reads RSS on an iPhone with Reeder Classic and on desktop in a browser. NewsBlur (self-hosted on
Host-A, now stopped) was too much; yarr (added 2026-09-24 as a stopgap, Fever API over Tailscale TLS)
is too little and has no Google Reader API; Miniflux (also running on Host-A) was rejected as too
plain. Kipple is a single-user reader built to the owner's spec: Go + SQLite + React in one image, Google
Feedly-style reading UI, server-side read/starred state, retention with starred protection, stats,
and a Google Reader API endpoint so existing reader apps (Reeder Classic, NetNewsWire, anything
else that speaks the FreshRSS dialect) can add rss.example.com as an account that syncs both ways.
Kipple is the web app plus that sync endpoint; there is no native app, and nothing about Reeder
is copied — the Reeder and NetNewsWire research exists only so the endpoint interoperates with
them on the first try. It replaces yarr at https://rss.example.com. The fixed decisions live in
`CLAUDE.md` and the brief pasted on 2026-09-24; this plan turns them into phases with verifiable
exits. Phase 1 is the only phase planned to implementation detail here; phases 2–4 get scope and
exit criteria and are re-planned after the owner's day of use.

Companion documents (written this session, to be committed under `docs/`):
- `docs/research/*.md` — nine primary-source research reports (Reader API as FreshRSS and Miniflux
  implement it, Reeder Classic, NetNewsWire, item-id/timestamp reconciliation, fetch-layer prior art,
  Go libraries, Cloudflare Access/tunnel, PWA/fonts).
- `docs/design.md` — data model, item ids, scheduler, retention, API mapping (judge-panel output).

## Research findings that shape the design

### Google Reader API contract (what Kipple must serve)

Sources: `docs/research/greader-freshrss.md`, `greader-miniflux.md`, `item-id-and-quirks.md`,
`reeder-classic.md`, `netnewswire.md`. Cross-corroborated by at least two independent reports
unless marked (single).

- **Prefix.** Reeder Classic's "FreshRSS" account type takes a host and appends `/api/greader.php/`
  itself; NetNewsWire has the user type `https://rss.example.com/api/greader.php` and appends
  `/accounts/ClientLogin` and `/reader/api/0/*`. Kipple serves the API only under
  `/api/greader.php` (also strip an accidentally doubled `/api/greader.php` prefix like FreshRSS).
  Reeder's generic "Reader" type uses root paths (Miniflux layout); not needed — the owner uses the
  FreshRSS type in both apps.
- **ClientLogin.** `POST /api/greader.php/accounts/ClientLogin`, form `Email`, `Passwd` (also accept
  GET). Success: `text/plain` `SID=<tok>\nLSID=<tok>\nAuth=<tok>\n`. The token must contain no `=`
  (NetNewsWire splits on every `=`): an HMAC token of 64 hex characters (design decision 10). Failure: `401` `text/plain`
  `Error=BadAuthentication` with headers `Google-Bad-Token: true` and `X-Reader-Google-Bad-Token:
  true`. Reeder immediately calls `GET reader/api/0/user-info?output=json` and treats 401 there as
  login failure; return `{"userId","userName","userProfileId","userEmail"}` (all strings).
- **Auth.** `Authorization: GoogleLogin auth=<tok>` on every request. `GET reader/api/0/token`
  returns the same token as plain text (NetNewsWire strips one trailing `\n`; FreshRSS pads to 57
  chars — irrelevant). POST writes carry `T=<tok>` (query or body). Kipple accepts a POST if the
  header is valid **or** `T` is valid; tolerate `T=x`/empty when the header is valid (Reeder 4
  legacy). Stale/invalid → `401` (NetNewsWire re-fetches the token once on 401/403, re-logs-in on
  401 during refresh). Never return 429 (NetNewsWire pauses all sync for an hour).
- **Item ids.** Signed int64. `stream/items/ids` emits `itemRefs[].id` as **decimal strings**;
  items emit `id` = `tag:google.com,2005:reader/item/` + zero-padded 16-hex; `continuation` is a
  **string**, omitted on the last page. Inbound `i=` arrives as long form (padded or not,
  NetNewsWire), bare 16-hex (Reeder), or decimal (Liferea): strip prefix → hex if it has a letter or
  a leading `0` → else decimal. Kipple ids are positive microsecond crawl timestamps (16 digits,
  never leading zero, < 2^60), so the rule is unambiguous.
- **Timestamps.** `published`, `updated` integers (seconds); `crawlTimeMsec`, `timestampUsec`
  strings. `timestampUsec` = crawl time (Reeder 4 sorted on it; FreshRSS/Google semantics),
  `published` = feed date (NetNewsWire uses only this). `ot`/`nt` in seconds; apply `ot` as
  `crawl_time >= ot OR state_changed_at >= ot` (FreshRSS), not published date (avoids NetNewsWire's
  known sync gap). `mark-all-as-read` `ts`: parse by digit count (≥16 µs, 13 ms, ≤10 s); cut on
  crawl time.
- **Request shapes actually seen.** Reeder: `subscription/list?output=json`; `stream/items/ids`
  reading-list `xt=read n=10000`; starred `n=10000`; `s=read ot=now-30d n=10000`; `token`; `POST
  stream/items/contents` with ≤100 bare-hex `i=`; `edit-tag` `a=`/`r=` read|starred;
  `mark-all-as-read s= ts=`. NetNewsWire: `tag/list`, `subscription/list` (conditional GET),
  `stream/items/ids` `n=1000` with `c=` continuation loop (reading-list `ot=`, unread no `ot`,
  starred no `ot`, `s=feed/N ot=`), `POST stream/items/contents` 150 long-form ids, `edit-tag`
  ≤1000 ids one `a=` or `r=` per POST, `subscription/quickadd` then re-list, `subscription/edit
  ac=edit` with `a=/r=/t=`, `ac=unsubscribe`, `rename-tag`, `disable-tag`, `subscription/import`
  (raw OPML, `Content-Type: text/xml`, no T, must be exactly 200). NetNewsWire polls unread+starred
  ids every ~120 s while active.
- **Response shapes that break Swift decoding if wrong.** `stream/items/contents` envelope
  `{"id":"user/-/state/com.google/reading-list","updated":<int>,"items":[...]}`; each item must
  have `id`, `summary:{content}`, `categories:[...]`, `origin:{streamId,title,htmlUrl}` where
  `streamId == subscription.id` (`feed/<n>`), `alternate:[{href,type}]`, `published`, `author`.
  Also send `content:{content}` and `canonical` (Miniflux does; harmless). Truncate content at
  500 KB. `subscription/list`: `{"subscriptions":[{"id":"feed/<n>","title","categories":[{"id":
  "user/-/label/<name>","label":"<name>"}],"url","htmlUrl","iconUrl"}]}` — `categories` always an
  array. `tag/list`: `{"tags":[{"id":"user/-/state/com.google/starred"},{"id":"user/-/label/<name>",
  "type":"folder"}...]}`. `unread-count`: `{"max":N,"unreadcounts":[{"id","count",
  "newestItemTimestampUsec"}...]}` (Reeder/NetNewsWire don't call it; implement for FeedMe-class
  clients). `edit-tag`, `mark-all-as-read`, `subscription/edit`, `rename-tag`, `disable-tag` →
  `text/plain` `OK`, **2xx even for unknown ids** (a non-2xx wedges NetNewsWire's queue forever).
  `quickadd` → `{"numResults":1,"query","streamId":"feed/<n>","streamName"}`.
- **Conditional GET on list endpoints.** NetNewsWire re-fetches `subscription/list` with its stored
  ETag right after `quickadd` and needs a 200 containing the new feed. The ETag is a hash of the
  rendered body, so it changes exactly when the list does and can never go stale.
- **Form parsing.** NetNewsWire leaves `;` unencoded in `t=/a=/r=` values; Go's `ParseForm`
  rejects semicolons. Kipple parses form bodies itself (split on `&` only, `QueryUnescape`).
- **Do not** fullwidth-escape `& < >` in titles (FreshRSS quirk; NetNewsWire un-escapes it).
- **Never rewrite image URLs to the proxy in API responses** — the proxy lives behind Access; Reeder
  would get 302s. Rewriting is UI-side only.

### Fetch layer (from `fetch-prior-art.md`)

Dedup key per feed with a type prefix (`g:` sha256(guid) › `l:` sha256(raw link) › `h:`
sha256(title+content)), plus `link_hash` for GUID-migration detection (≥50 % and ≥5 items new by
uid but matching by link → re-key instead of insert). ETag/Last-Modified stored verbatim and sent
back; body SHA-256 short-circuit for servers that ignore validators; manual refresh ignores
validators and backoff but still respects a live per-host 429/503 `Retry-After`. Status table:
200 parse; 304 touch; 301/308 record target and migrate the URL only after 3 consecutive permanent
chains to the same target with no other feed owning it and no https→http downgrade; 302/303/307
follow only; 404/4xx/5xx/timeouts/DNS/TLS → error + backoff; 410 → disable with reason; 429/503 →
honor `Retry-After` per host. Backoff `min(interval × 2^(n−1), 24 h)` with ±20 % jitter, reset on
any 2xx/304; never auto-disable except 410; flag "failing" after 14 consecutive failures.
User-Agent `Mozilla/5.0 (compatible; Kipple/<ver>; +https://rss.example.com)`, per-feed override;
`Accept` list as Miniflux; body cap 10 MiB on the decompressed stream; dial 10 s, header 15 s,
total 30 s; ≤5 redirect hops; SSRF guard in `Dialer.Control` after resolution (private, loopback,
link-local, CGNAT, multicast). Concurrency: scheduler tick 60 s, `next_fetch_at <= now`, semaphore
8, per-host 2; one DB writer goroutine, one transaction per feed; initial `next_fetch_at` spread
across the first interval. Retention runs in the same transaction as the insert, ranks non-starred
items not seen in this fetch by `published_at DESC, id DESC`, tombstones everything past N in
`trimmed(feed_id, uid, item_id, read, trimmed_at)` so a re-seen item never returns as unread.
Feeds that lie about encoding: decode to UTF-8 ourselves before `gofeed.Parse`.

### Cloudflare Access and tunnel (from `cloudflare-access-deploy.md`)

One new Access self-hosted app `rss.example.com/api/greader.php` with a single **Bypass / Everyone**
policy; the existing `rss.example.com` OTP app keeps protecting everything else. No wildcard. Delete the
old `/fever` bypass app once yarr is retired. Kipple enforces its own auth on the bypassed prefix and
answers 401 text, never a redirect. Ingress rule becomes `{"hostname":"rss.example.com","service":
"http://192.0.2.50:7080"}` with no `originServerName` (a PUT to the tunnel configurations
endpoint replaces the whole ingress array — GET, edit one rule, PUT all back including the 404
catch-all; or use the dashboard). Trust `X-Forwarded-Proto`/`CF-Connecting-IP` only when
`RemoteAddr` is the tunnel host (`KIPPLE_TRUSTED_PROXY_IPS=192.0.2.192`). Session cookie
`kipple_session`, `HttpOnly`, `SameSite=Lax`, `Secure` only when the effective scheme is https,
`Max-Age` 90 days (longer than the Access session; ask the owner to set the Access session to 1 month so
the OTP prompt is rare). SSE works through named tunnels (`text/event-stream` is flushed) with a
15 s heartbeat and `Cache-Control: no-cache, no-transform`; verify with `curl -N` after cutover.
`Cache-Control: private, no-store` on every API/JSON/HTML response. iOS standalone PWAs have their
own cookie jar (login once more inside the PWA; keep all auth in the HttpOnly cookie).

## Design (`docs/design.md`)

Produced by a judge panel: three independent designs (API-first, fetch-first, simplicity-first),
three judges, a synthesis, three red-team critics (client compatibility, SQLite/concurrency, the owner's
product rules) and a revision that dispositioned all 37 red-team issues (§12). The lemon24/reader
comparison added twelve more items (§13). The load-bearing decisions:

- **Scheduler.** One dispatcher goroutine owns all scheduler state; 8 workers, 2 per host, talk to
  it only over channels. Tick 30 s, `next_fetch_at` per feed, backoff
  `min(interval·2^(n−1), max(24 h, interval))` with jitter, Retry-After per host in memory, manual
  refresh as a tracked run whose progress streams over SSE.
- **SQLite.** `modernc.org/sqlite`, three pools on one file (one-connection writer reachable only
  through `WithWrite`, four-connection read pool, one snapshot connection for `VACUUM INTO`), a
  one-slot commit gate so a Reeder `edit-tag` waits for at most one feed commit. STRICT tables,
  hand-rolled migrations with `application_id`, `items` split into a narrow state row and
  `item_content` so read/star changes rewrite small cells.
- **Item ids** are crawl-time microseconds from a monotonic allocator inside the commit; one integer
  is the rowid, `timestampUsec`, the continuation cursor and the `ot`/`nt`/`ts` key. Inbound ids:
  anything with `/` is hex; otherwise leading `-` or digits without a leading zero are decimal; else hex.
- **Reader API.** A front handler owns every Reader path (so ServeMux never 301s a POST), a custom
  raw-preserving form parser, n+1 lookahead for continuation, no JSON `null`, writes always 2xx,
  `subscription/list`/`tag/list` ETag = hash of the rendered body (cannot go stale), `ot` =
  arrival or server-side content change (never read/star changes), all content URLs made absolute
  at ingest, image URLs never rewritten in API responses.
- **Retention.** Newest N by `sort_at` per feed, starred exempt, trim on every successful fetch and
  when N changes. A trimmed ledger keeps id/uid/read, and a 90-day restore stub means starring or
  un-reading a trimmed item on a client restores it with the same id instead of being silently undone.
- **Unsubscribe** keeps starred items in a hidden archive feed that stays in `subscription/list`
  while non-empty.
- **Stats.** `Recorder.Record(tx, …)` writes in the same transaction as the state change; one `open`
  kind with a `client` field; API read inference is **off** by default because NetNewsWire batches
  marks and no count threshold separates reads from bulk marks. Events keep feed/title snapshots and
  never cascade from items.
- **Auth.** Web: argon2id password, persistent HttpOnly `kipple_session` cookie, same-origin check
  plus a required `X-Kipple-Client` header on state-changing requests. Reader API: a separate
  generated 24-character API password, a stateless HMAC token (no `=`), one verification at a time
  with a success memo so clients re-running ClientLogin cost nothing.
- **Memory.** `GOMEMLIMIT=64MiB` plus ≤34 MB SQLite page caches; compose `mem_limit: 256m`; contents
  endpoints stream row by row.

The package layout, DDL, per-endpoint SQL and test plan are in design §2, §6, §9 and §10.

  the other within 60 s; OPML export from Kipple re-imports losslessly; retention trims to the cap
  and never touches starred items (test by starring an old item and lowering a feed's cap).
- the owner uses it for a day before phase 2 starts.

## Open decisions (defaults chosen unless the owner objects)

1. **Adding a feed from Reeder or NetNewsWire** (design decision 33). Default: the API inserts the
   feed and returns immediately with no outbound HTTP, keeping "API clients never trigger fetches"
   literal; the scheduler fetches it within 30 s, so the first client sync shows the feed with no
   items and the next sync fills it in. Alternative: fetch synchronously during the add (up to 8 s)
   so the first sync is complete.
2. Retention default **250** per feed (choices 50–unlimited). Alternative: 500.
3. Separate generated API password for the Reader API (design decision 10) rather than reusing the
   web password on the public path. the owner types it once into each app.
4. API read inference for stats stays **off** until the first day's request log shows whether
   Reeder's single-article marks can be told apart from scroll marks; until then, stats count web
   opens only.
5. Web cookie lifetime **90 days**; the owner raises the Access session for the UI app to 1 month.

## Model and effort for execution

The session model is Sonnet at medium effort for phase 1 implementation. Subagents always get
explicit `model` and `effort`: Sonnet at medium for reading, research and routine code; Opus at high
for review, judging and ambiguous root-causing. Nothing runs at max, and there are no multi-agent
fan-outs unless the owner asks. `/code-review high` before the deploy step runs on Opus. Implementation
agents read `docs/design.md` by section, never whole.

## Risks

- **Usage limits** killed several workflow runs during planning; the policy above and memory
  `subagent-model-and-effort` exist because of it.
- **Reeder's `mark-all-as-read` `ts` unit** is unrecorded anywhere public; digit-count parsing
  covers all three possibilities. Verify on first use by watching Kipple's request log.
- **modernc.org/sqlite libc pairing** — pin exactly; `ncruces/go-sqlite3` is the fallback with a
  one-file switch.
- **Cloudflare challenge on feed hosts** keys on TLS fingerprint, not UA; expose per-feed
  `disable_http2` and browser-UA overrides from day one so the owner can fix a blocked feed himself.
- **Feedburner/http feeds (88)** will mostly 301 to https on the first cycle; the migration rule
  handles it, but the health view must make the notices readable rather than alarming.
