# 2026-10-12 (Monday): no single-key shortcuts, cheaper CI, a release commit left open

Two merges and one pull request left open. Main ended the day at `52c9ae1`.

## What changed

- **All single-key shortcuts removed (#408, 00:03).** The owner's decision: the web app has no keyboard shortcuts that are not
  accessibility. Every letter and symbol key went through one global keydown hook, with a keymap, an overlay and a Settings
  switch to turn it off. The switch existed only because the keys clash with assistive technology. Removing the keys removed
  the hook, the overlay and the switch: 52 files, 215 insertions, 1,604 deletions. Kept: Tab order and the list's one Tab stop,
  arrow keys between rows and in sidebar trees, Enter, Space, Escape. The server still accepts `client.shortcuts` in a stored
  profile and ignores it, so an old profile never turns into a 400.
- **Follow-ups (#412, merged 13:18).** With shortcuts gone and the list one Tab stop, the arrows only worked when focus was on a
  row's link. Where Tab skips links (Safari defaults) a keyboard user could reach only the first row's star and menu buttons and
  could not leave that row. ArrowUp and ArrowDown now work from any control in a row, and Esc on Search goes back.
- **CI cost (#411).** A pull request cost about 41 job-minutes. Docs, test and `tools/` only changes now run Browser UAT on
  Chromium alone; the fuzz run is sharded four ways with a kept corpus; a queued commit on `main` keeps its result instead of
  being dropped. Review took three rounds, the cap. Follow-ups #409 (corpus cache size) and #410 (shard stability). The
  expected saving is an estimate; the workflow had not run on GitHub when it merged.
- **Release commit for 0.9.0-beta.2 (#413, 18:05, left open).** It folds 5 fragments, no schema change. Gates ran on `52c9ae1`:
  Opus whole-diff review without blockers, Go twice (two different timing tests each flaked once and passed alone), fuzz, web
  tests, changelog check and starter feeds. `node --test scripts/*.test.mjs` failed inside the gate run and passes standalone on
  the same commit (107 of 107); the cause was not found. It was not tagged.

## What it taught

- The keymap kept producing focus and selection bugs (#390, #395, #403 all concern keys acting on a different row than the
  one with focus). Deleting it was cheaper than another design for a cursor that two kinds of input had to share.
- Removing a feature has a contract tail: the profile field, docs, the README, UAT checks (K3 now checks that letter keys do
  nothing) and an accessibility document all named the shortcuts.
