## Review findings

- **P1 (decided, no change):** with no setup code, an unclaimed instance behind a tunnel or proxy can be claimed by
  whoever reaches it first, because the Host gate is the only barrier on that path. Options were to refuse forwarded
  claims or to document it. The owner chose neither (DECISIONS.md, 2026-10-03).
- **P2, all fixed in #198:** docs said the setup route answers 404 where it answers 401 after a restart; the open-mode
  sign-in screen ignored the new 409; stale wizard step numbers; a `setup-token` stub kept only to announce a removal at
  runtime; migration 0011 left the dead keys inside device profiles (now stripped, and the read-side filter removed);
  two "no account yet" log lines at start (now one).
- **Checked and sound:** concurrent claims (exactly one 201), CSRF and Origin checks, DNS rebinding (421), cookie flags,
  the open-mode peer rule on IPv4-mapped, CGNAT, ULA and link-local addresses and on the live-update stream, removal of
  `open_lan` from code, UI, API and docs, migration idempotence, refusal of schema 11 by 0.6, changelog fragments.
